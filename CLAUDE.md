## Commands

```bash
npm run dev          # vite dev server on port 3000
npm run build         # production build (outputs to .output/)
npm run start          # run the built server: node ./.output/server/index.mjs
npm run preview       # preview production build, host+port 3000
npm run test           # vitest run
npm run lint            # biome lint
npm run format         # biome format
npm run check           # biome check (lint + format)

npm run db:generate    # drizzle-kit generate migrations from schema.ts
npm run db:migrate     # apply migrations
npm run db:push        # push schema directly (no migration file)
npm run db:pull        # introspect DB into schema
npm run db:studio      # drizzle studio UI
```

There is no test suite in `src/` yet even though Vitest/Testing Library are configured — `npm run test` will currently report no tests found.

To run a single test file once tests exist: `npx vitest run path/to/file.test.ts`.

## Architecture

This is a TanStack Start (React 19 + TanStack Router, file-based routing) app called "bird" — a personal collection of small side-project games, deployed under the `/bird` base path (see `base`/`basepath` in `vite.config.ts` and `src/router.tsx` — keep these three in sync if the deploy path ever changes).

### Routing
- File-based routes live in `src/routes/`. `src/routeTree.gen.ts` is auto-generated by the TanStack Router plugin — never edit it by hand (it's gitignored from Biome checks and marked read-only in `.vscode`).
- `src/routes/__root.tsx` defines the shared HTML shell (`Header`/`Footer`, TanStack Query provider, global styles).
- Files/dirs prefixed with `-` inside a route folder (e.g. `src/routes/defy/-defy.functions.ts`) are route-scoped, non-routable helper modules — this is where server functions for that route live.

### Server functions & the `defy` game
`src/routes/defy/-defy.functions.ts` is the core server logic for the daily word-guessing game:
- `getWordOfDay` (server-only) picks a word for the current day: day-of-week maps to a word-frequency difficulty range (`difficultyMapping`), a candidate is pulled from the DB, then validated against the external `freedictionaryapi.com` API (retried up to `MAX_RETRIES` times if the API has no usable entries/definitions). Results are cached in-memory per day (`cache[dateSeed]`).
- `guessWord` and `getWord` are client-callable `createServerFn` endpoints. `getWord` computes how many hints/definitions to reveal based on number of guesses + hints used so far, and only returns the full word/answer once `gameOver` is true — do not add a code path that returns the answer earlier.
- The "today" concept is always US Central time (`getCurrentFormattedDate`, `getCentralDayOfWeek` in `src/lib/utils.ts`), not UTC or server-local time — reuse these helpers rather than computing dates directly.

### Data layer
- SQLite via `@libsql/client` + Drizzle ORM. DB file is `bird.db` at the repo root; connection in `src/db/index.ts`, schema in `src/db/schema.ts`, query helpers in `src/db/queries.ts`.
- Single table `word_frequencies`: word list with frequency rank, a computed difficulty score/tier, `wordInApi` (flag set to false when the dictionary API has no entry for a word, so it's skipped in future selection), and `timesUsed` (words are chosen least-used-first, then randomly, to avoid repeats).
- `drizzle.config.ts` reads `DATABASE_URL` from `.env.local`/`.env` (currently `file:./bird.db`). Note `.cta.json` (the original TanStack CLI scaffold record) says `postgresql`, but the project actually runs on `sqlite` — trust `drizzle.config.ts`/`schema.ts` over `.cta.json`.

### Client state
Two persisted TanStack Store stores, both synced to `localStorage` and rehydrated on load in `typeof window !== "undefined"` guards:
- `src/lib/guess-store.ts` (`guessStore`): per-day game state (guesses, hints used, game over/won). Keyed by `gameOverDate`; state is discarded on load if that date doesn't match "today" (Central time), so a new day always starts fresh.
- `src/lib/app-store.ts` (`appStore`): cross-day app state, currently just whether the instructions dialog has been seen.

### UI
- Tailwind CSS v4 (via `@tailwindcss/vite`) + shadcn/ui ("new-york" style, components under `src/components/ui`). Add new shadcn components with `pnpm dlx shadcn@latest add <component>` (per `.cursorrules`); import aliases are `#/*` and `@/*` → `./src/*` (see `components.json`/`tsconfig.json`).
- `src/routes/typers/` is a second, unrelated mini-game (falling-word typing game) built with `@pixi/react`/`pixi.js`; it renders client-only (`ssr: false`) since it depends on `window`.

### Build & deploy
- Nitro (via `nitro/vite`) builds the standalone server output to `.output/`. `Dockerfile` is a two-stage build (Node 24 alpine) that copies `.output/` into the production image and runs `node .output/server/index.mjs`; the SQLite DB file is expected to live alongside it in a mounted volume (see the `touch bird.db && chown` step).
- `.github/workflows/deploy.yml` builds and pushes `ghcr.io/dabass2/leinad-bird:latest` on push to `main`/`master`.

## Conventions
- Biome (not ESLint/Prettier) enforces formatting (tabs, double quotes) and linting, with import organization on save. Run `npm run check` before considering a change done.
- `src/routeTree.gen.ts` and `src/styles.css` are excluded from Biome checks — don't hand-edit either.
